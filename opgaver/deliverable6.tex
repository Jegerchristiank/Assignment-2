\begin{enumerate}
\item \textbf{Initial exploration. What kind of data is logged in the file? Assuming data quality is good, how can the data be used to answer the RQs?}

\textbf{Answer:}
The log is a case-based radiology event trace with timestamped workflow events, actors/roles, resource types, and optional contextual attributes (modality, report/coding and notes fields). The initial profile is documented in Appendix~\ref{app:part2_supporting}, Table~\ref{tab:d5_log_profile}, and the complete logged activity set is listed in Table~\ref{tab:d5_logged_activities}.

If data quality were high and stable, the same structure could support all three RQs:
\begin{itemize}
  \item \textbf{RQ1 (efficiency/bottlenecks):} stage-level and total turnaround-time calculations, queue-delay analysis, and role/shift bottleneck localisation.
  \item \textbf{RQ2 (critical communication):} case-level conformance checks for whether critical findings are communicated and within clinically acceptable time windows.
  \item \textbf{RQ3 (AI triage):} feature extraction for urgency, modality, reporting workflow, and workload context to support prioritisation models.
\end{itemize}
In practice, later method outputs show that these uses are possible but quality-constrained (especially by missingness, representativity skew, and timestamp credibility).

\item \textbf{Method selection justification. Include your completed method selection table from Part 3. Additionally, answer why you did \textit{not} choose the other methods, what trade-offs were considered, and how RQs influenced selection.}

\textbf{Answer:}
The completed selection table is provided in Appendix~\ref{app:part2_supporting}, Table~\ref{tab:d5_method_selection}. I selected M2, M6, M8, M10 and M11 to cover all three RQs while keeping the analysis interpretable and non-redundant.

\textbf{Why these five methods:}
\begin{itemize}
  \item \textbf{M2} provides a baseline quality gate before any interpretation (relevant to all RQs).
  \item \textbf{M6} tests representativity (urgency/time coverage), critical for RQ1 and RQ3.
  \item \textbf{M8} directly targets RQ2 patient-safety communication conformance.
  \item \textbf{M10} links RQ1 performance metrics to timestamp credibility (batch logging risk).
  \item \textbf{M11} adds human/workload context for RQ1 operational realism and RQ3 data-bias risk.
\end{itemize}

\textbf{Why the other methods were not selected:}
\begin{itemize}
  \item \textbf{M1} (schema) was useful but low-yield once required columns were present.
  \item \textbf{M3} (ICD-11 accuracy) was narrower and less central to the selected RQ focus than timing/representativity.
  \item \textbf{M4} (actor equity) overlapped substantially with M11 workload-distribution outputs.
  \item \textbf{M5} (modality representativity) was partly subsumed by broader representativity framing in M6.
  \item \textbf{M7} (temporal sequence conformance) is valuable, but M10 was prioritised because it combines KPI relevance with timestamp-credibility sensitivity.
  \item \textbf{M9} (modality-specific attribute rules) is clinically useful but relatively narrow for this report's cross-RQ synthesis.
\end{itemize}

\textbf{Trade-offs considered:}
\begin{itemize}
  \item \textbf{Breadth vs depth:} five methods gave cross-RQ coverage without over-fragmenting interpretation.
  \item \textbf{Direct RQ alignment vs technical checks:} preference was given to methods with explicit safety/performance/AI relevance.
  \item \textbf{Redundancy control:} overlapping methods were deprioritised to avoid repeating the same finding with different labels.
\end{itemize}

\item \textbf{Results interpretation. Provide detailed interpretation of results from each chosen method (key results, interpretation, expectation check, and primary facets).}

\textbf{Answer:}
Key outputs are summarised in Appendix~\ref{app:part2_supporting}, Table~\ref{tab:d5_key_results}, with supporting figures in Figures~\ref{fig:d5_viz_missingness}--\ref{fig:d5_viz_workload}.

\paragraph*{M2 (Completeness)}
\textbf{Key result:} high missingness in several context fields (Appendix Table~\ref{tab:d5_key_results}, Figure~\ref{fig:d5_viz_missingness}).  
\textbf{Interpretation:} process-event reconstruction is feasible, but context-rich interpretation (especially for triage development) is weakened.  
\textbf{Expectation check:} expected direction confirmed.  
\textbf{Primary facets:} Data, Source, System.  
\textbf{Possible improvement:} enforce field-level completion rules tied to event type and clinical purpose.

\paragraph*{M6 (Representativity)}
\textbf{Key result:} urgency and shift imbalance (Appendix Table~\ref{tab:d5_key_results}, Figure~\ref{fig:d5_viz_representativity}).  
\textbf{Interpretation:} observed data are not evenly representative across operational contexts, limiting generalisation of performance and AI conclusions.  
\textbf{Expectation check:} broadly expected, but skew magnitude was stronger than anticipated.  
\textbf{Primary facets:} Data, Task, Human.  
\textbf{Possible improvement:} stratified sampling windows and richer metadata for case context.

\paragraph*{M8 (Critical communication conformance)}
\textbf{Key result:} mostly conformant, but one failed critical case with missing communication event (Appendix Table~\ref{tab:d5_key_results}).  
\textbf{Interpretation:} even a single missed communication event is clinically meaningful for RQ2.  
\textbf{Expectation check:} expected near-complete compliance; finding one failure was plausible and important.  
\textbf{Primary facets:} Task, System, Human.  
\textbf{Possible improvement:} mandatory linkage between finalisation and communication events for critical cases.

\paragraph*{M10 (TAT with batch-logging detection)}
\textbf{Key result:} total TAT differs materially between raw and cleaned estimates; a substantial share of cases were batch-logging flagged (Appendix Table~\ref{tab:d5_key_results}, Figure~\ref{fig:d5_viz_tat}).  
\textbf{Interpretation:} operational KPI conclusions are highly sensitive to timestamp credibility.  
\textbf{Expectation check:} partially expected; impact size was the most surprising result.  
\textbf{Primary facets:} Data, System, Task.  
\textbf{Possible improvement:} explicit event-entry provenance (real-time vs retrospective) and stricter timestamp auditing.

\paragraph*{M11 (Workload distribution)}
\textbf{Key result:} uneven role and actor concentration (Appendix Table~\ref{tab:d5_key_results}, Figure~\ref{fig:d5_viz_workload}).  
\textbf{Interpretation:} human-resource patterns are non-uniform, influencing both efficiency analysis and fairness/generalisability claims.  
\textbf{Expectation check:} expected concentration confirmed.  
\textbf{Primary facets:} Human, Task, System.  
\textbf{Possible improvement:} combine event-load with case-complexity and shift context before drawing staffing conclusions.

\item \textbf{Per-Facet Data Quality Synthesis. For each facet, assess findings, main issues, and consequences for RQs. Then discuss the most challenging facet and alternative assessments.}

\textbf{Answer:}
This synthesis draws on Appendix~\ref{app:part2_supporting}, Tables~\ref{tab:d5_key_results}--\ref{tab:d5_custom_facet_mapping} and Figures~\ref{fig:d5_viz_missingness}--\ref{fig:d5_viz_workload}.

\paragraph*{Data facet}
The strongest issues are high missingness and temporal-credibility sensitivity. Main consequence: RQ1 and RQ3 estimates are vulnerable to measurement bias when key context fields or trustworthy timestamps are absent.

\paragraph*{Source facet}
Source-process heterogeneity and non-operational contamination signals indicate that dataset provenance is mixed. Main consequence: RQ3 model-development assumptions can fail if training data provenance is not separated.

\paragraph*{System facet}
System capture gaps appear in critical communication and timestamp logging practices. Main consequence: RQ2 safety conformance and RQ1 KPI trust are constrained by what the system does (or does not) enforce.

\paragraph*{Task facet}
Task-level quality is uneven: urgency/shift skew and communication-rule dependence indicate partial task alignment. Main consequence: conclusions may overfit recorded workflow rather than actual operational priorities.

\paragraph*{Human facet}
Workload concentration and documentation behaviour materially shape observed data. Main consequence: both efficiency and AI readiness can be misinterpreted without human-practice context.

\textbf{Most challenging facet:} \textit{Human} (closely followed by Source), because event logs provide limited access to intent, informal coordination, and local workarounds.

\textbf{How facets could be assessed better:}
\begin{itemize}
  \item Extend logs with provenance and entry-mode metadata.
  \item Add targeted qualitative follow-up (short interviews/observations) for high-impact anomalies.
  \item Use cross-system linkage (RIS/PACS/communication traces) to reduce invisible-system boundaries.
  \item Apply periodic documentation-practice audits with feedback loops.
\end{itemize}

\textbf{Why activities are not logged (technical/social/economic):}
\begin{itemize}
  \item \textbf{Technical:} phone/verbal interactions occur outside core system schemas.
  \item \textbf{Social:} many coordination steps are informal, negotiated, and context-dependent.
  \item \textbf{Economic/workload:} comprehensive documentation increases burden and can reduce clinical throughput.
\end{itemize}

\textbf{How event-log-only models fail and consequences for RQs:}
\begin{itemize}
  \item \textbf{RQ1:} bottleneck attribution misses informal reprioritisation and coordination delays.
  \item \textbf{RQ2:} communication pathways appear cleaner than practice, masking safety-critical handoffs.
  \item \textbf{RQ3:} AI models risk learning an incomplete process representation, reducing robustness and fairness.
\end{itemize}

\textbf{Parallel with Part I (interview vs observation):}
The same pattern recurs: stated/formal traces underrepresent situated adaptation. In Part I, this appeared as interview-observation deltas; in Part II, it appears as workflow-log deltas.

\textbf{Implication for data-driven healthcare IT:}
Data-driven approaches are necessary but insufficient when taken as complete reality proxies. They should be coupled with qualitative discovery and governance-aware interpretation \parenciteshort{guidehealthinformatics2026ch9and27,guidehealthinformatics2026ch27}.

\textbf{One concrete logging-system change:}
Introduce a lightweight \texttt{communication/coordination} event type (e.g., consultation, clarification, reprioritisation) with minimal mandatory fields: timestamp, role, linked case, reason code, and optional short note.

\textbf{Trade-offs and mitigation (Chapter 9 formal/informal framing):}
\begin{itemize}
  \item \textbf{Why full logging is difficult/unwelcome:} over-formalisation can create documentation burden, surveillance concerns, and workflow friction.
  \item \textbf{Mitigation:} keep fields minimal, use role-level rather than excessive personal granularity, and prioritise high-impact contexts (critical findings, reprioritisation points) over universal exhaustive capture.
\end{itemize}
