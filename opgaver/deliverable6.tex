\subsection{Deliverable 6: Part II Reflection Questions}
\label{sec:deliverable6}

\begin{enumerate}
\item \textbf{Initial exploration and relevance to the three research questions.}  
The dataset contains 150 events, 17 cases, 14 columns, and 12 activity types across 2026-01-12 07:45 to 2026-01-13 08:46. Core workflow fields are present, while context-heavy fields are sparse (e.g., \texttt{study\_uid}, \texttt{series\_count}, \texttt{instance\_count}, \texttt{icd11\_code}). Following the \textit{Five Facets} framework, this means the dataset is stronger for \textit{Task/System} sequence analysis than for rich \textit{Data/Source/Human} interpretation \parencite{mohammed2025fivefacets}. Applied to this case, the file can support RQ1 (\textit{TAT}/bottlenecks), RQ2 (\textit{conformance} for critical communication), and RQ3 (\textit{representativity} and workload patterns), but with explicit limits on contextual inference.

\item \textbf{Method selection justification and trade-offs.}  
M2, M6, M8 (15 min), M10, and M11 were selected as a \textit{coverage portfolio}: together they cover all three RQs with low redundancy across facets. The full selection is documented in Appendix~\ref{app:part2_supporting}, Table~\ref{tab:d6_method_selection}. Non-selected methods (M1, M3, M4, M5, M7, M9) were excluded due to overlap or narrower RQ relevance. The core trade-off was breadth across \textit{facets} versus depth in fewer dimensions.

\item \textbf{Results interpretation by method.}  
Chapter 27 explains that \textit{process mining} uses temporal event sequences to reveal common pathways and frequent exceptions \parenciteshort{guidehealthinformatics2026ch27}. Applied here, Appendix~\ref{app:part2_supporting}, Table~\ref{tab:d6_method_results} shows:
\begin{itemize}
  \item M2: high context missingness (e.g., \texttt{study\_uid} 134/150), so flow-level findings are feasible but context-sensitive claims are weaker.
  \item M6: urgency and shift imbalance (15 stat/urgent vs 2 routine; Day 11, Night 6, Evening 0), so \textit{representativity} for broad generalisation is limited.
  \item M8: 16 pass and 1 fail on critical communication; overall \textit{conformance} is high, but the single fail remains operationally important for RQ2.
  \item M10: 6/17 cases with \textit{batch-logging} signatures and a large raw-vs-clean TAT gap (147.93 vs 198.50 min), making timestamp credibility a central RQ1 risk.
  \item M11: uneven actor distribution (radiographer 64 events, resident 7, system actor concentration), indicating workload concentration affecting interpretation.
\end{itemize}

\item \textbf{Proposed DQ dimension.}  
The proposed dimension is \textit{Batch Logging Credibility}: whether timestamp structure reflects real-time documentation or delayed/post-hoc entry. The motivating pattern is repeated timestamps and tight clustering in cases such as CXR-013 and CXR-011. In this context, low credibility biases RQ1 (\textit{TAT} and bottlenecks), can mask RQ2 communication delay, and can leak artefactual timing patterns into RQ3 modelling. Facet mapping is documented in Appendix~\ref{app:part2_supporting}, Table~\ref{tab:d6_custom_facet_mapping}.

\item \textbf{Per-facet data quality synthesis.}  
The custom method code is documented in Appendix~\ref{app:d6_custom_code}. It scores per-case timestamp risk from duplicate-time frequency, short-window event density, and low unique-timestamp ratio.
\begin{itemize}
  \item \textit{Data}: missing context fields and timestamp artefacts reduce precision.
  \item \textit{Source}: mixed real-time and delayed logging reduces reliability.
  \item \textit{System}: safety-relevant communication events can be missing despite completed workflow.
  \item \textit{Task}: skewed representativity limits external validity for optimisation/triage.
  \item \textit{Human}: tacit coordination is weakly represented in logs.
\end{itemize}
Most challenging facet is \textit{Human}; stronger assessment would combine log analytics with targeted qualitative validation.

\item \textbf{Invisible work and system design implications.}  
The completed invisible-work table is in Appendix~\ref{app:part2_supporting}, Table~\ref{tab:d6_invisible_work}. A model based only on log traces tends to overestimate formal linearity and underestimate coordination work. In Chapter 9 terms, this is a \textit{formalisation continuum} problem: complete formalisation is neither realistic nor always desirable \parencite{guidehealthinformatics2026ch9and27}. This aligns with the declarative workflow argument that robust process support should balance \textit{flexibility} and \textit{constraints}, not force one rigid path \parencite{vanderaalst2009declarative}. In this case, a practical improvement is lightweight optional contextual events (consultation, reprioritisation reason, communication intent) to improve visibility without heavy documentation burden.
\end{enumerate}
